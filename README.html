Open the app in your browser

The app is a web page. To see it, you start it once from a terminal window, and then everything happens in your browser. You don't need to read or change any code. It takes about five minutes the first time.

From the zip file

Run it on your computer

Follow the steps below. It runs only on your machine, needs no account or password, and doesn't need the internet once installed.

Which computer are you using?

  1. Open a terminal window

    Press ⌘ Command + Space, type Terminal, and press Return. A window with a blinking cursor opens.

    Click the Start menu, type PowerShell, and press Enter. A window with a blinking cursor opens.

    What is this? A terminal is a window where you type commands instead of clicking. You'll paste in a few lines, one at a time, and press Enter after each.

  2. Check that Python is installed

    Python is the free software the app runs on. Paste this and press Enter:

    python3 --version
    py --version

    You should see something like Python 3.9.6. Any version 3.9 or higher is fine.

    If you see "command not found" or an older version: download Python from python.org/downloads and install it. On the first install screen, tick "Add python.exe to PATH". Then close the terminal, open a new one, and try again.

  3. Go to the project folder

    Unzip the file you received. You'll get a folder, usually called meridian-pipeline-main.

    In the terminal, type cd followed by a space. Then drag the folder from FinderFile Explorer into the terminal window; its location fills in automatically. Press Enter.

    cd ~/Downloads/meridian-pipeline-main
    cd $HOME\Downloads\meridian-pipeline-main

    Why? This tells the terminal which folder to work in. The example above works if the folder is in your Downloads.

  4. Set up the app (first time only)

    Paste these lines one at a time, pressing Enter after each. The last one takes about a minute and prints a lot of text; that's normal.

    python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
    py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

    What does this do? The first line makes a private space for the app inside its own folder, so nothing is installed elsewhere on your computer. The second switches into that space; you'll see (.venv) at the start of the line. The third downloads the one data library the app needs.

  5. Start the app

    python app.py

    You should see your web browser open to the app automatically, at http://127.0.0.1:8765. If it doesn't open, copy that address into your browser.

    Keep the terminal window open while you use the app; closing it stops the app. When you're finished, click the terminal and press Ctrl + C.

Opening it again later

Open a terminal, go to the folder (step 3), then:

source .venv/bin/activate
python app.py

For everyone

How the design earns trust

Meridian's previous AI reporting tool produced wrong numbers and mixed up segments, and lost leadership's confidence. The likely cause: it let an AI model produce figures directly. Language models give the most plausible-sounding answer, and a plausible wrong number looks exactly like a right one. This prototype is designed so that can't happen, and so anyone can check it when in doubt.

A quick AI tool, same file

Enterprise has closed $165,000 against a $3,650,000 Q2 quota: 4.5% attainment. Enterprise is well behind target.

This tool

Enterprise has booked 4.5% of its Q2 quota, but with open pipeline it's at 1.03x: technically covered, with no room for slippage.

Both use the same numbers. Only one reaches the right conclusion, and shows the rows, formula and caveats behind it.

Eight design choices, and where you'll see them

1. The AI never produces a number

Every figure is calculated by ordinary code from the deal records. At most, an AI model helps turn the question into a structured request, and every field it fills is checked. The version you're running uses no AI model at all.

Why it matters

This removes the failure that cost the last tool its credibility.

2. Every answer shows its evidence

The file, the date the data was pulled, the exact filters, every deal row with its line number, and the formula with its inputs.

In the app

Source data and Method sections; click any [A] or deal ID.

3. It shows how it understood you

Before any number, the answer restates the question as the tool read it: which segment, rep and period.

In the app

The "Read as" line at the top of every answer.

4. Definitions are printed, not assumed

What "this quarter", "at risk" and "same point" mean, and which data extract was used, appear on every answer that relies on them. If a leader defines them differently, they can see it immediately.

In the app

The Assumptions section.

5. It refuses rather than guesses

Unknown people, ambiguous names, unsupported periods and forecasts are refused, with the reason and how to rephrase. A refusal costs a minute; a wrong number costs the tool.

In the app

Try the "Try to break it" questions.

6. It warns you about the data itself

Trust Flags point out what could mislead you about this specific answer: deals moved between quarters, reused deal IDs, stale close dates, or reps short inside a healthy-looking total.

In the app

The Trust Flags section, open by default.

7. Missing data never becomes zero

A blank deal value makes the figure "at least"; a missing quota makes a ratio "undefined"; a verdict too close to call says "unknown". Nothing is quietly filled in.

Why it matters

Silent zeros are a quieter form of hallucination.

8. It is tested against known answers

142 automated checks, including the core questions pinned to figures worked out independently from the data files, and runs on deliberately damaged copies of the data.

Why it matters

Correctness is checked before anyone sees an answer, not after.

Where it still falls short

  • Correct maths on flawed data is still flawed. The tool makes data problems visible; it doesn't fix the CRM.
  • The definitions are the builder's, not yet Meridian's. They need sign-off from the sales operations team.
  • It understands a limited set of phrasings. It hasn't been tested on how Meridian's leaders actually ask questions, so some reasonable questions will be refused.
  • Evidence only helps if someone looks at it. A reader who stops at the headline is relying on the design, not verifying it.
  • It's a prototype on sample data: 10 reps, 92 deals, two data extracts, with no live CRM connection and no scale testing.

Definitions used

  • "This quarter" means Q2 2026, because the data is current as of May 2, 2026.
  • "Same point" means the same number of days into each quarter.
  • "At risk" means closed-won plus open pipeline is below quota. Open pipeline is counted at full value, not weighted by stage.

Glossary

Terms you'll see in the app, in plain language.

Quota
The sales target for a rep or segment for the quarter.
Bookings / closed-won
Deals already won, counted at their value.
Attainment
Bookings divided by quota. 50% means half the target is already won.
Open pipeline
Deals still being worked (not yet won or lost) that are expected to close this quarter.
Coverage
Bookings plus open pipeline, divided by quota. 1.00x means that if every open deal closed, the target would be exactly met.
Segment
A customer group: Enterprise, Mid-Market or SMB.
Extract / snapshot
A copy of the sales data taken on a particular date. This data has two: one at the end of Q1, and one on May 2.
Trust Flag
A warning about something in the data that could mislead you about a specific answer.
Naive tool
For comparison only: the answer a quick AI tool would give by taking the file at face value.

For technical reviewers

How it's built

Python standard-library web server plus pandas. No web framework, no API key required.

From question to answer

  1. Parse (meridian/query.py): question → structured query, fields as written.
  2. Validate (validate.py): check against the rep roster and snapshots.json, or reject with every problem listed. No deal data is read yet.
  3. Select (selection.py): rows chosen by readable filters; rows failing load checks are set aside and named, never counted.
  4. Compute (metrics.py): figures, formulas, assumptions and flags.
  5. Render (serialize.py): JSON for the page, which formats and computes nothing itself.

If ANTHROPIC_API_KEY is set, Claude fills step 1's fields only and never sees a deal value. By default a rule-based parser is used.
